# 4年 オペレーティングシステム 講義ノート

オペレーティングシステムの講義ノート。
Obsidianを使用しています。

## Tips等

- ファイル名の規則は、`No.--_mm-dd`で、講義Noが1ケタ台は、`0-`の形式で。
- 連立方程式みたいな文字のやつは、`hspace{}`を使うと良い。

## 技術背景

Windows版Obsidianでは、WSL内のファイルシステム上に保管庫を作成するとファイル監視の競合やパフォーマンス低下が発生するため、Linux環境とのシームレスな共有に壁がありました。
また、メイン環境のArch Linux（デスクトップ）とWSL上のUbuntu（ラップトップ）で共通のノート環境を構築する必要がありました。
そこで、**WSLg**と**Flatpak**を用いて、WSL上にLinux版Obsidianをインストールし、ネイティブ環境でノートを管理・Git共有する方法を採用しました。

### 1. WSLg

WSL内部でWaylandサーバ (Weston) が自動的に立ち上がり、Linuxアプリの描画情報をWindows側のRDPレールを介して転送する仕組み。これにより、Windowsデスクトップ上でLinux GUIアプリを直接操作できる。

### 2. Flatpak

Flatpakは、Linuxにおけるサンドボックス型のパッケージ管理システム。

- **依存関係の解決**: 実行に必要なライブラリ（ランタイム）を共通のプラットフォームとして管理、あるいはパッケージに同梱する。これにより、デスクトップ（Arch Linux）とWSL（Ubuntu）という異なるディストリビューション間でも、ライブラリのバージョン差異を気にせず、全く同じObsidianの動作環境を再現できる。
- **サンドボックス構造**: アプリがシステムから隔離された環境で動作するため、OS側のライブラリが古い場合や不足している場合でも、Obsidianのような複雑なElectronアプリを安全かつ安定して実行できる。

### 3. なぜこの構成が有効なのか

- **ファイル監視の安定化**: Windows版Obsidianでネットワークパス (`\\wsl$\...`) を介して保管庫を開くと、ファイル監視 (File Watching) が正常に機能しない。WSL内で完結させることで、Linuxカーネルの機能（inotify等）を直接利用でき、動作が安定する。
- **Linuxネイティブのパフォーマンス**: ファイルアクセスがLinuxネイティブ (Ext4) の速度で行われるため、インデックス作成や全文検索が高速。
- **メンテナンス性**: `flathub` リポジトリを利用することで、最新のObsidianをコマンド1つで導入・更新できる。
